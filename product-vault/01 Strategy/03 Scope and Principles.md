# Scope and Principles

## Product Principles

1. **Memory Before Notes**: The daily surface serves capture and recall. Library is durable infrastructure, not the product’s center of gravity.
2. **Text Before Chrome**: Low-chrome, content-first surfaces. One primary action is visually dominant per state.
3. **Structure After Capture**: Body text is sufficient. Kind, source, cue, folder, and timing are optional or defaulted.
4. **Attempt Before Answer**: A due memory never exposes its stored body until the user explicitly chooses to reveal it.
5. **Calm Over Compulsion**: No streaks, overdue guilt, scores, confetti, or red backlog badges.
6. **Local Truth**: Plain Markdown files on device are authoritative.
7. **Failure Must Be Visible**: Never clear a draft, navigate away, or claim success before a verified durable write.
8. **Honest Portability**: Human-readable Markdown with 1-click export so users truly own their data.
9. **Native Quality**: Hardware keyboard, safe areas, back gestures, font scaling (200%), and TalkBack/VoiceOver are non-negotiable.
10. **Evidence Before Breadth**: Graphs, AI, and complex sync wait until the core memory loop earns them.

---

## What is in v1

- **Core Loop**: Capture (Note, Book learning, Experience) and In-App Cue-First Recall (1d / 4d / 14d intervals).
- **Surfaces**: Today, Library (hierarchical folders + search), and Settings (privacy, storage, export).
- **Navigation**: Clean 3-tab layout with stack navigation and unsaved changes guards.
- **Storage & Portability**: App-private UTF-8 Markdown files with 1-click vault backup export.
- **Local Reminders**: Optional, privacy-safe local notifications with deep links.

---

## Deferred Until Evidence

- Global graph visualization and backlink dashboards
- AI chat, auto-tagging, or AI-generated summaries
- Cloud accounts, social feeds, and multi-user sync
- Tasks, calendars, habits, goals, and streaks
- Attachments, images, audio recording, and PDF clippers
- Rich text / WYSIWYG editors, plugin systems, and theme stores
- Complex SRS algorithms (e.g. SM-2, FSRS)

---

## The Scope-Change Filter

A new feature enters the core product only if it:
1. **Materially improves Capture → Recall → Reuse**
2. Cannot be solved simply with the existing text-first flow
3. Does not compromise 100% offline and privacy guarantees
4. Has a clear user-facing rationale and measurable acceptance criterion
5. Displaces something of lower value rather than bloating the calm interface
